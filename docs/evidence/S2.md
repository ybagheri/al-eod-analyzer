## Direction convention for wedge/climax (user rule: direction = implied direction of the pattern's CONSEQUENCE, same as the trap rule)

Stored (pre-v3-extractor) population sampled and scanned (population = all 243 labels):

- `climax` (65 rows): keyword-decidable sample of 10 + full population
  cross-tab `buy x direction` / `sell x direction`:
  buy->bull 19/21, sell->bear 26/36 — **stored data predominantly used MOVEMENT
  convention** (buy climax = up). Reviewer's batch-1 reading of `09bb32c388fa`
  ("Buy Climax" -> bear) used the consequence convention.
  => convention conflict between stored rows and the declared rule.
- `wedge` (258 rows): top->bear 29/37 (consequence-like) but bottom->bull 44/89
  and bottom->bear 45/89 — **NOT one consistent convention**; 132 rows have no
  directional keyword ("Parabolic Wedge", "Minor Wedge", ...).

Decision (per user): the declared pipeline convention is consequence-implied;
the stored rows are NOT mass-normalized now (that would change direction, an
ADR-013-protected attribute). The conflict is logged as an **S3-entry
normalization/review decision item**. The extraction prompt is NOT changed
mid-calibration; direction agreement must therefore be reported separately for
convention-dependent kinds (`wedge`, `climax`) vs the rest in the S2 closure.
